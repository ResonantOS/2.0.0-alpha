# Agent conventions

## License header — mandatory on every file

Every file created or modified in this repo (source, config, scripts, YAML,
Dockerfiles, notebooks, markdown — no "small file" exemption) carries this
header, placed after a line-1 shebang/doctype when one exists, and separated
from any pre-existing comment block by a blank line:

```
// Augmentor — dsh-augmentor plugin, pipe, and Chromium extension
// Copyright © 2026 Manolo Remiddi
// SPDX-License-Identifier: MIT
// License: MIT — see LICENSE at the repository root.
```

- Comment style per language: `//` JS/TS, `#` sh/py/yaml/env, `/* */` CSS,
  `<!-- -->` HTML/MD/SVG.
- JSON files cannot carry comments — leave them as-is.
- Never remove or rewrite an existing header when editing a file.
- Files generated by the installer (`bin/pipe-host.sh`) get the header from
  the template in `install-native-host.sh` — keep the two in sync.

## Build & test

```sh
node test/install-proof.mjs                  # deterministic fresh-user install proof (no user state touched)
PROOF_LLM=1 node test/install-proof.mjs      # + real agent drives the headless browser (needs LLM creds in env)
PROOF_SOURCE=npm PROOF_LLM=1 node test/install-proof.mjs   # npm plugin path
cd test && node m3-e2e.mjs && node sw-e2e.mjs && node panel-e2e.mjs \
  && node chrome-e2e.mjs && node m2-e2e.mjs && node tools-e2e.mjs \
  && node updates-e2e.mjs   # e2e battery (needs the real local DSH app)
sh plugin/tests/boot/run.sh                  # plugin boot test
```

Version lockstep: `plugin/package.json` and `extension/manifest.json` versions
must match; `pipe.mjs` reads the pipe version from the manifest dynamically.
